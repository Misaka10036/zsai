# Python 后端功能检查（2026-09-21）

范围：智盛fontend 的现有页面、PHP 转发层与本仓库 Python 后端。未修改 Go 后端。

## 本次修复

- `js/app.js` 的图谱构建操作检查 HTTP 状态、JSON、业务 code 和 task_id。只有确认创建任务才提示已提交；权限不足、空知识库、任务重复、网络失败等错误不再提示成功。
- 图谱读取失败不再显示“尚未构建”和构建按钮；页面明确显示加载失败。ECharts 未加载时也显示错误。
- 使用现有 Python 路由 `POST /api/v1/datasets/{dataset_id}/index?type=graph`，无须替换端点。提交成功不等于任务执行完成。
- 两套门户测试由旧的 `docker/vivarly` 改为本目录，增加图谱错误回归和请求与 Python 路由的匹配检查。

## 实际验证

- PHP 契约测试：20 项通过，其中一个参数化测试覆盖 34 个 JSON 接口封装；已发送的请求均检查 Python 路由和 HTTP 方法。包含上传文件名、部分失败、搜索 SSE、会话归属和图谱提交错误。模拟服务不执行实际解析或模型推理，也不证明所有请求字段和业务语义均正确。
- 页面测试：图谱提交 8 种响应、图谱读取 4 种失败，以及管理员和普通用户搜索选择、回答展示、HTML 清理通过。
- 本目录全部 PHP 文件的 `php -l`、全部独立 JavaScript 文件的 `node --check` 通过。
- 本机配置读取到 RAGFLOW_BASE_URL 为 `http://localhost:9222`；API key 已配置（未输出密钥）。连接该地址失败。单独探测 `127.0.0.1:9380` 和 `127.0.0.1:8080` 也未获得 HTTP 响应；门户数据库连接被拒绝。
- `start_frontend.ps1` 默认通过环境变量覆盖为 `http://127.0.0.1:9380`。直接启动 PHP 时需确认本地配置指向实际 Python 服务。未擅自修改现有本地配置。
- 尚未完成真实服务端到端验证；不能据此宣称所有功能可用。

## 功能与已确认的限制

| 功能 | 检查结果 |
|---|---|
| 登录、注册、用户管理 | 使用独立门户 MySQL，不使用 RAGFlow 账号登录。本机数据库不通，无法验证实际登录及用户 CRUD。禁用用户只更新数据库，现有 PHP Session 未重新检查用户状态，已登录用户不会立即退出（`auth.php`、`api.php`、`db.php`）。 |
| 知识库创建、修改、删除 | 存在 Python 对应路由。嵌入模型等依赖仍需在后端配置，真实创建未验证。知识库列表只取前 50 项，接口错误可能被呈现为空列表（`js/app.js`）。 |
| 文档上传 | 多文件请求与部分失败保留已通过模拟验证。页面没有逐项显示成功/失败，混合结果会显示整体失败；上传完成只刷新列表，不自动解析（`js/dataset.js`）。 |
| 文档解析、停止、编辑、删除 | 选中文档解析、停止等按钮确实调用 PHP/Python 接口；实际任务执行、解析器和存储依赖未验证。文档列表没有先检查业务 code，失败可能显示为无文档（`js/dataset.js`）。另有未被当前页面按钮使用的 `parseAllUnparsedFiles` 占位函数，仅弹窗，不应当作可用功能（`js/app.js`）。 |
| 全局文件管理 | 文件夹、上传、移动、删除、关联知识库的封装已核对路由；实际存储写入、下载和目录导航未做端到端验证。 |
| 图谱读取、构建 | Python 路由存在，本次修正错误提示。普通用户页面仍会展示空图谱的“立即构建”，但 PHP 要求管理员，普通用户点击会被拒绝。后台任务完成情况需 worker、文档和模型联调。 |
| 搜索 | 已配置的搜索应用可进入既有请求链路，模拟回答与引用处理通过。门户新建搜索应用只传名称、描述，页面未调用配置更新；Python 搜索要求 `kb_ids`，新建应用需先到原版后台绑定知识库（`js/search.js`、`api/apps/restful_apis/search_api.py`）。 |
| 搜索引用预览 | 文本预览有实现；PDF 引用进入 PDF.js 渲染函数，但两个搜索页面都未加载 PDF.js，当前会提示“PDF.js 未加载”。非 PDF 文件统一按文本读取，不能等同于 Word/Excel 正确预览（`js/search.js`、`views/*/search.php`）。 |
| 搜索思维导图 | PHP 搜索收集器只返回 answer/reference，未传出 mindmap；普通用户搜索页也未加载 ECharts，因此这项展示不能认定可用。 |
| 聊天助手与会话 | 选择现有助手、创建/删除会话、读取历史和问答已有链路；会话归属检查通过模拟验证。依赖后台先创建助手并配置知识库、模型。历史/列表读取错误可能显示为空数据。 |
| 聊天展示 | 非流式返回，当前主要显示文本而非引用来源。新建会话后设置 currentSessionId，再加载列表，但不会调用 switchSession/fetchSessionMessages 清空旧消息；原会话内容可能留在新会话视图中（`js/chat.js`）。 |
| 请求切换 | 搜索/聊天没有请求顺序或会话响应归属保护，等待回答时切换应用/会话，旧响应可能写入新视图；重复提交也未限制。 |
| Agent | 创建、执行等封装有 Python 路由；停止按钮不调用后端取消，仅修改页面。执行请求未带回已有 session_id，连续运行不保证延续会话。详情失败会显示默认流程，不能据此判断实际流程正常（`js/agent.js`）。 |
| 页面资源与入口 | 多个页面依赖公网 Bootstrap/ECharts；内网不可达时影响展示和弹窗。页脚“文档/API”等链接为 `#`，普通用户首页 Agent 入口仅弹提示，属于占位入口。 |

## 真实环境验收顺序

1. 启动门户 MySQL、Python API 及其依赖与解析 worker；确认 PHP 的后端地址和 API key 可用。
2. 管理员登录，新建专用测试知识库，上传文本/PDF，执行解析并确认完成及切片数。
3. 在原版后台配置搜索应用与聊天助手关联该测试知识库；门户检索与多轮问答，核对答案、历史和会话隔离。
4. 管理员构建图谱，确认任务完成后刷新能显示图谱；验证空知识库、权限不足、重复构建和服务失败时的提示。
5. 验证文件下载/预览、编辑、停止解析、删除，以及用户管理。仅清理本次创建的测试资源。
